
# Smart Coach Therapy Loop Fix Plan

## Target Experience (Turn-by-Turn)

```
Turn 0: Maya states goal + plan ("Today we're working on food words. We'll talk, practice, then use what you practiced.")
Turn 1: Diagnostic probe ("What's something you like to eat?")
Turn 2: Deeper probe — stay diagnostic, don't expand ("What goes in it? What do you call that?")
Turn 3: Probe OR drill — if breakdown detected (circumlocution, hesitation, can't retrieve), fire Slot 1
Turn 4: If no breakdown at 3, probe again. Collect gap words.
Turn 5: LATEST Slot 1 fires — even with weak signal. If user is perfect, skip Slot 1 entirely.
Turn 6-7: Transfer bridge — force user to USE drilled words in a sentence/scenario. Lasts 2+ turns until verified.
Turn 8: Mandatory Slot 2 — reinforcement drill targeting same or related gaps
Turn 9-10: Transfer bridge again — verify generalization
Turn 11-12: Open conversation — check spontaneous use of practiced words
Turn 13: Wrapup — name exact words they retrieved, connect to real life
```

## Key Design Decisions

1. **Orient_assess forces `warmup` mode for turn 0, then `expand` for turns 1-3** — the state machine cannot override this to `scaffold` or `support` during assessment (we need to SEE the struggle, not fix it yet)
2. **Warmup mode block removed from drill evaluator** — drills can fire from any mode
3. **Gap words collected every turn during orient_assess** — fed directly into drill config
4. **Pre-drill narration is deterministic, rendered BEFORE the drill modal** — not generated by LLM
5. **Post-drill bridge enters transfer_bridge mode for 2-3 turns** — exits only when user produces a meaningful response using a drilled word
6. **Objectives driven by objectiveAdvancer (not timer)** — re-wire runCoachTurn to use it
7. **ACTION and CUE merged** — only send CUE when mode is scaffold/support
8. **Turn 6 unconditional fallback removed** — arc is sole drill authority

## Implementation Order (5 Fixes)

### Fix 1: Wire orient_assess mode override + collect gap words
**Files:** `sessionArc.ts`, `runCoachTurn.ts`
- Add orient_assess override in `getArcModeOverride()`: force `warmup` on turn 0, `expand` on turns 1-3
- Call `extractGapWords()` every turn during orient_assess phase
- Call `recordGap()` to accumulate gaps in arcState
- Pass `identifiedGaps` to drill selector when drill fires

### Fix 2: Remove warmup drill block + fix Turn 6 fallback
**Files:** `drillTriggerEvaluator.ts`
- Remove `if (state.mode === 'warmup')` block (line 62-64)
- Remove unconditional Turn 6 fallback (lines 114-121)
- Keep cooldown and max-2-drills-per-session checks

### Fix 3: Wire pre/post drill narration into the turn pipeline
**Files:** `runCoachTurn.ts`
- When `drillTrigger.kind` is set, include `getPreDrillNarration()` output in the result
- Add `preDrillNarration` and `postDrillBridge` fields to `CoachTurnResult`
- SmartCoach.tsx should render pre-drill text as Maya's message before opening the drill modal
- After drill completes, render post-drill bridge as Maya's first message back

### Fix 4: Fix transfer mode duration — require verified word use
**Files:** `sessionArc.ts`, `runCoachTurn.ts`
- Don't exit transfer mode after 1 turn
- Check if user's utterance contains any `drilledWords` before exiting
- Max 3 turns in transfer mode (then exit regardless to avoid frustration)
- Add `transferTurnsRemaining` counter to ArcState

### Fix 5: Merge ACTION/CUE in prompts + make prompts phase-aware
**Files:** `promptBuilder.ts`
- Only include CUE instruction when mode is `scaffold` or `support`
- In `expand` mode, only send ACTION (the CUE is just expansion_prompt, which is redundant)
- Make orient_assess prompt explicitly say "You are ASSESSING, not helping yet"
